# A股机会雷达策略优先开发方案

## 1. 方向修正

当前项目不能继续把开发重心放在 K 线视觉、筹码峰和按钮位置上。这个产品的核心能力应该是：

```text
稳定数据 -> 策略计算 -> 信号解释 -> 机会池 -> 人工跟踪 -> 复盘验证 -> 策略优化
```

前端只是把这个过程展示清楚；真正决定产品价值的是策略是否能持续发现值得看的股票，并能说明为什么值得看。

## 2. 策略分层

策略不能全部叫“买入信号”，需要按成熟度和用途分层。

| 层级 | 含义 | 前端动作 |
| --- | --- | --- |
| CandidateRanking | 初筛排序，找出值得看的股票 | 进入观察池 |
| PatternValidation | 日线/周线/结构条件验证 | 标记为结构符合 |
| TriggerConfirmation | 盘中触发确认，如放量、承接、突破 | 标记为候选机会 |
| ReviewOnly | 暂时只能复盘/模拟，不用于强提示 | 只进入模拟观察 |

## 3. 策略信号协议

每个策略输出必须包含：

```text
股票代码
股票名称
策略编码
策略名称
策略类型
策略阶段
建议动作：观察 / 候选 / 等回踩 / 确认 / 排除
置信度：低 / 中 / 高
综合分
价格
命中原因
风险提示
诊断指标
标签
```

这一步已经在代码中开始落地：

```text
StrategyStage
StrategySignalAction
StrategySignalConfidence
StrategyDataRequirement
StrategyDefinition
StrategySignal 扩展字段
GET /api/strategies
```

## 4. 现有策略复用判断

交接文档中的策略需要全部保留，但不能全部当作强买入。

| 策略 | 当前定位 | 处理方式 |
| --- | --- | --- |
| 主线板块共振 | 初筛观察 | 先做 CandidateRanking，后续接真实板块强度 |
| 逆势走强 | 初筛观察 | 接入市场环境后实现 |
| 强势趋势延续 | 结构验证 | 需要历史 K 线 |
| 平台放量突破 | 候选机会 | 先做实时触发，再补平台结构 |
| 均线回踩再启动 | 等回踩/候选 | 需要历史 K 线和均线结构 |
| 强修复反弹 | 实验观察 | 先做模拟池 |
| 大A梦想家长期观察 | 长期观察/模拟 | 不做强买入，只做观察和复盘 |
| 中和应泰主升低吸观察 | 观察/低吸体系 | 先转公式规则，分主图趋势和触发条件 |

## 5. 后端大流程

### 5.1 实时扫描

```text
定时任务触发
  -> 获取实时行情快照
  -> 候选排序策略并行运行
  -> 对候选加载历史 K 线
  -> 结构验证策略运行
  -> 触发确认策略运行
  -> 多策略合并评分
  -> 生成机会池和信号流水
  -> SignalR 推送前端
```

### 5.2 历史验证

```text
选择日期范围
  -> 从 DuckDB 读取历史 K 线
  -> 按交易日回放行情
  -> 运行策略
  -> 记录历史信号
  -> 计算 1日/3日/5日/10日表现
  -> 生成策略胜率、回撤、收益分布
```

### 5.3 策略优化

```text
历史表现统计
  -> 人工标记结果
  -> 找出误报/漏报
  -> 调整策略参数
  -> 再次回测
  -> 固化参数版本
```

## 6. Python 策略接入方案

Python 策略不直接操作 UI，也不直接写机会池。它只负责计算，C# 负责调度和落库。

```text
C# 生成策略输入 JSON
  -> 调用 Python runner
  -> Python 输出标准 StrategySignal JSON
  -> C# 校验结果
  -> 合并评分
  -> 入库和推送
```

建议约束：

```text
Python 策略必须无状态
一次输入，一次输出
输出必须带 strategy_code、reason、metrics
异常不能影响其他策略
每个策略有超时时间
```

## 7. 下一步开发顺序

### Step 1：策略清单和策略定义展示

后端已经新增 `/api/strategies`。下一步前端增加“策略中心”，展示每个策略的阶段、动作、数据要求和参数。

### Step 2：历史 K 线注入策略上下文

现在策略上下文已经预留：

```text
DailyBarsBySymbol
MinuteBarsBySymbol
Parameters
RunMode
```

下一步要在扫描流程中先筛候选，再给候选补历史 K 线。

### Step 3：实现第一个真实结构策略

优先选择“平台放量突破”：

```text
先用实时快照筛候选
再读取最近 60 根日线
判断平台区间、压力位、突破幅度、成交量放大
输出诊断指标
```

### Step 4：历史回放引擎

用 DuckDB 对一段时间做策略回放，生成历史信号和后续表现。

### Step 5：Python 策略 runner

接入 Python 后，优先用于复杂指标、公式转换和批量计算。

## 9. 开发运行约束

当前后端以控制台/未来 Win 服务方式运行时，会锁定 `AShareRadar.ServiceHost/bin` 目录下的 DLL。开发时如果服务未停止，`dotnet build` 可能出现 DLL 被 `.NET Host` 占用的问题。

后续需要补充：

```text
开发环境停止脚本：只停止 AShareRadar.ServiceHost 相关进程
正式 Win 服务控制：安装、启动、停止、重启脚本
构建前检查：发现服务占用时给出明确提示
发布构建：输出到独立 publish 目录，避免覆盖运行目录
```

原则：

```text
开发构建前必须可控停止后端
不要用停止所有 dotnet 进程的方式处理
正式环境必须通过 Windows Service 控制命令优雅停止
```
